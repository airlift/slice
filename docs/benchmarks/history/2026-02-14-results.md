# RE2 Benchmark Results

This document contains historical benchmark data comparing Java and C++ RE2
implementations. It is not current release qualification; the final matrix will
be rerun on dedicated Intel and Arm machines after correctness work is complete.

For benchmarking methodology, see [METHODOLOGY.md](../METHODOLOGY.md).
For detailed root-cause analysis of gaps, see [2026-02-14-gap-analysis.md](2026-02-14-gap-analysis.md).

---

## Test Environment

**Java:** Apple M-series, JDK 25.0.2, JMH 1.37, 3 forks, 10x1s warmup, 5x1s measurement.
**C++:** Same hardware, AppleClang 17.0.0 `-O3`, Google Benchmark 1.9.5, 5 repetitions, 0.5s minimum.
**C++ extra suites (sections 4.1-4.3):** `cpp-baseline-004.csv` (3 repetitions, 0.3s minimum).

### FullMatch DotStar `(?s).*`

The historical run used a Java-only UTF-8 shortcut that was later removed
because it accepted malformed UTF-8. Those UTF-8 numbers do not describe the
current implementation. Latin-1 dot-all and UTF-8 `\C*` remain valid
byte-universal constant-time cases.

| Mode   |        Java |         C++ |                     Winner |
|:-------|------------:|------------:|---------------------------:|
| UTF-8  | Removed historical shortcut | O(n) | Rerun required |
| LATIN1 | O(1) ~50 ns | O(1) ~20 ns |                 C++ faster |

## Summary

| Category               | Result                                                                                                                             |
|:-----------------------|:-----------------------------------------------------------------------------------------------------------------------------------|
| **DFA throughput**     | Easy0 1.1x slower, Easy1 1.2x slower, Medium 1.1x slower, Hard 1.2x faster.                                                        |
| **NFA throughput**     | Hard 256K 1.2x faster, Parens 256K 1.1x faster; see full table for other sizes.                                                    |
| **Search extra**       | Mixed after engine campaign: AltMatch OnePass and BigFixed DFA improved; Easy2 DFA and BigFixed RE2 remain slower.                 |
| **Parse extra**        | SplitHard substantially faster; SplitBig remains slower; SearchPhone is faster at tiny size and ~1.1x-1.2x slower on larger sizes. |
| **Misc utilities**     | Dot/ASCII near parity; `possibleMatchRange*` remains slower and is deferred (non-engine hot path).                                 |
| **Fast rejection**     | Both implementations stay in constant-time ranges on rejection workloads.                                                          |
| **FullMatch `(?s).*`** | Java remains O(1) for UTF-8 while C++ UTF-8 path is O(n).                                                                          |
| **Compile**            | One-time compile costs reported in section 3.1/3.2.                                                                                |
| **Parse (OnePass)**    | 1.3x slower.                                                                                                                       |
| **Parse (RE2 full)**   | 5.3x slower.                                                                                                                       |
